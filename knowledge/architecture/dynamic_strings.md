# M6: dynamic string table and dependency observation

> A dependency name observed from DT_NEEDED is a declaration, not a resolved or loaded module.

SourceArtifact -> elf::inspect -> dynamic::dependencies::observe(elf, dynamic_limits, string_limits)
-> source-bound string references -> generic Dependency::Named values in InspectedArtifact.
No ELF-specific name model enters the generic dependency vector or load-plan metadata.

## Evidence and scope

Primary format evidence, read 2026-09-08: [gABI string tables](https://gabi.xinuos.com/elf/04-strtab.html)
and [dynamic tags/dependency declarations](https://gabi.xinuos.com/elf/08-dynamic.html). References are
byte offsets into NUL-terminated data; substrings and repeated references are meaningful. These facts
do not specify a host-path policy or grant dependency resolution. The implementation independently uses
generated bytes, not PS5Rust code or decrypted/catalogue input. Error and resource policies below are
explicit Astero decisions rather than Sony assumptions.

## Ownership and API

- elf/dynamic/string_table/{view,error}.rs owns DynamicStringTable, StringReference and lookup failures.
- elf/dynamic/dependencies/{inspect,model,error}.rs owns DT_NEEDED interpretation, reference provenance,
  work budgets and adaptation into the existing generic inspected-artifact contract.
- loader/dependencies/name.rs owns DependencyName and its construction invariants.
- loader/dependencies/requirement.rs owns the corrected generic Dependency declaration enum.

M6 observe calls the unchanged M5 observation stage against the same ElfInspection. Its read-only
DependencyObservation retains the M5 report, an optional string table, references and enriched
InspectedArtifact. Dynamic observation still preserves unimplemented tags. The source is cloned as a
handle only; source identity/length remain authoritative. No independent source/table pair is accepted.

DynamicStringTable::from_dynamic returns None for a report with no string descriptor; a zero-size
source-backed descriptor instead returns Some(empty table). M5 already translated the complete
STRTAB/STRSZ extent through PT_LOAD and checked actual source bytes. M6 consumes that private validated
descriptor and checks its token against the retained owner, rather than recomputing a different mapping.
Absent PT_DYNAMIC, absent STRTAB and an empty table remain observable distinctions in the report.

## Bounded string references

lookup(offset, max_scan_bytes) requires offset < declared table size, then searches at most the lesser
of the remaining declared extent and explicit scan budget. NUL must occur inside that window. The
returned StringReference borrows original immutable bytes and carries a source-bound content token;
both exclude the terminator. Offset/source additions fit by the whole-table proof. No C pointers,
unsafe conversion, raw externally indexed memory or scan beyond DT_STRSZ is used.

| Case | Behavior |
|---|---|
| Offset zero at NUL | Valid empty byte string |
| Offset points into an existing string | Valid bounded suffix through its terminator |
| Offset points to the final NUL | Valid empty string; one byte of scan work |
| Offset equals/exceeds size, including offset zero in an empty table | OffsetOutOfBounds |
| No NUL through declared end | MissingTerminator, even if source bytes immediately after the table contain NUL |
| Budget ends before declared end without finding NUL | ScanLimit; no truncated successful name |
| Non-UTF-8 bytes | Valid byte view; explicit as_utf8 returns a standard Utf8Error |

The view is a bounded reference interpreter, not a whole-table conformance certificate. It does not
scan unreferenced strings or enforce global first/last-NUL layout. Referenced strings must actually
terminate. In particular it does not assume offset zero is empty without reading its byte. Empty lookup
values are valid, but an empty required dependency name is rejected by the generic name contract.

## Byte identity and generic dependency correction

M2's Dependency { module: ModuleId } could express only caller-assigned graph requirements; deriving
such an ID from DT_NEEDED would invent resolution. Dependency now distinguishes:

- Module(ModuleId): explicit caller graph requirement; original non-self/unique admission rules apply.
- Named(DependencyName): an unresolved name; exact declaration order and repeated values are retained.

DependencyName owns nonempty, NUL-free Box<[u8]> storage. Its bytes are immutable through the public API.
It does not impose UTF-8, ASCII, case folding, slash rules, normalization, path interpretation or a
filename extension. as_utf8 validates explicitly and never modifies the stored bytes; there is no
lossy conversion in authoritative metadata. Literal byte identity may require a later display policy.
A NUL-containing or empty externally constructed name fails with DependencyNameError before it can
be inserted as a Named declaration. There is no fallback name or generated module ID.

The existing dependencies fields on ArtifactDescription and TargetMetadata now carry these variants;
LoadPlan continues cloning the admitted metadata without resolution. Admission skips module-ID set
checks for constructor-validated Named values and preserves repeats. Existing imports still reference
ModuleId and require a matching Module declaration; a Named declaration never satisfies that check.
There is no name-to-module mapping or dependency availability test. M2 module-ID fixtures were adapted
to the enum spelling while retaining all their existing rejection tests.

## DT_NEEDED provenance, budgets and lifetime

NEEDED entries are read in original dynamic order. Each points to a bounded string; its bytes become
one owned generic name. NeededReference retains the original dynamic-entry index, string offset and
checked source token for diagnostics. Equal offsets and equal byte names at different offsets remain
separate declarations. No sorting, set-based normalization or cross-dependency identity is inferred.
Unknown unused strings are not interpreted.

StringLimits explicitly supplies max_scan_bytes_per_reference and max_total_scan_bytes. Both count
lookup bytes including each terminating NUL; repeated offsets are charged again. The effective lookup
budget is min(per-reference, remaining-total). A failed lookup ends the operation without a partial
successful report. ScanLimit retains that effective limit. Successful charged scans also bound owned
name payload bytes; M5's separate entry limit bounds declaration/reference counts. Name validation
and copying cost linear work in the accepted byte lengths, in addition to charged lookup work.
No global cache, hidden name-length limit or source-size ceiling is introduced. Excessively generous
caller budgets still permit corresponding host work/allocation; standard allocator behavior remains.

Tables and views share SourceArtifact storage, so no whole-table copy occurs. Small dependency names
are deliberately owned to let format-independent metadata survive independently of parser lifetimes.
Repeated names currently have separate small allocations; preserving semantics and explicit budgets
is preferred over premature interning. The report retains source lifetime for its diagnostic tokens;
a borrowed StringReference cannot outlive its table owner. Detached metadata cannot mutate the report.

## Boundaries and errors

M5 errors remain earlier than string interpretation: missing/incomplete descriptor groups, duplicate
STRTAB/STRSZ (even equal duplicates), unmapped/BSS/crossing/overflow/source failures, and NEEDED offsets
outside the declared table. These are nested as DependencyObservationError::Dynamic, retaining their
original context. The M5 out-of-range index counts NEEDED declarations; it is not a raw dynamic index.

StringTableError adds OffsetOutOfBounds, MissingTerminator, ScanLimit and nested Source errors. Each
lookup failure retains its string offset and table token (source identity, location and length).
DependencyObservationError::Lookup adds the original dynamic-entry index; InvalidName additionally
retains offset and DependencyNameError. TableUnavailable is a defensive invariant error: normal missing
NEEDED/STR_TAB relationships already fail in M5. Invalid UTF-8 is not a dependency error because names
are byte-oriented; optional text access returns Utf8Error. No arithmetic failure is converted to success.

Enriched InspectedArtifact retains all original deferred requirements. PT_DYNAMIC images still fail
admission with UninspectedProgramSemantics; learning names is not completing dynamic semantics. A
separate synthetic contract test transfers parsed declarations into the M2 fixture to prove generic
admission/plan preservation and that names do not satisfy module-ID imports. It does not clear the
ELF guard or claim an ELF image is loadable.

## Optional conventional tags: bounded decision

SONAME fits future observed module-name metadata, but existing ModuleMetadata identifies a caller's
module graph node and display label. M6 will not silently replace either with SONAME. RPATH/RUNPATH
require separate byte-oriented search-metadata contracts and precedence/security decisions when search
is authorized. None is necessary to declare NEEDED names. All three therefore remain numeric Unknown
tags with raw values in the retained M5 report, not silently interpreted or resolved. A future focused
extension can reuse these string mechanics without treating SONAME as identity or implementing search.

## Validation and remaining work

[Generated tests](../../crates/astero-loader/tests/dynamic_strings.rs) reuse the M5 byte builder and
cover 18 cases plus one name-immutability compile-fail doctest. Sweeps exercise 146 offset/budget
combinations across six tables, 13 dependency counts/repeated offsets and 12 source-boundary pairs.
See [validation](validation.md) for executed evidence and fresh index counts.

No dependency search/loading, HLE/provider/sysmodule lookup, NIDs, symbol/relocation parsing, GOT/PLT
semantics, SELF, filesystem/mmap, guest mappings, runtime modules, PS5Rust migration or execution.
Existing alignment, admission overlap scaling and future load-bias pressures are unchanged. Names
still need a future resolution policy; symbols still need trusted total extent/count evidence.
Recommended M7: bounded symbol-table extent contracts and observations from generated bytes, stopping
before binding/resolution. M7 has not started.
